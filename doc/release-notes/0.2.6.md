# Cached packages, early bibliography, steadier CI

### Site

- `feat` **The playground's examples compile without a download.** The site build runs each example with pdfLaTeX and ships every TeX Live file the build reads, fonts too, beside the playground. Compile in the browser now asks the site first and the package server only for the rest. What TeX Live lacks (a font's `.vf`) is asked of nobody, and an example whose build looks for a missing file is reported by the build.
- `feat` **The font picker offers what the engine can set, each with a sample.** pdfLaTeX offers the font packages installed (EB Garamond, Fira Sans, Kp Fonts, STIX Two, XCharter and more), fontspec the OpenType fonts, plus the machine's own fonts as a list to filter. Each offer shows "Aa Bb 123" as TeX sets it, drawn into the preview sheet with the TikZ pictures (`font:` sprites), which the site ships.
- `fix` **The showcase videos are recorded on an idle machine only, one compiling take at a time, at low priority.** Taken during a busy build they showed a compile five times as slow as it is and loaded the machine further (`SATEX_SHOTS=force` records anyway).
- `fix` **A command typed into the PDF echoes what it typesets.** `\TeX`, `\LaTeX` or a logo of your own showed nothing until the build. The echo now sets what the run sets for the command alone, with its kerns and its raised and lowered letters (`satex/commandText`).
- `fix` **A click on the date of a title page puts the caret into `\date`.** Text that `\maketitle` sets from a stored argument after another one (the date after the author) was refused as "code satex cannot place".
- `fix` **A finding's hover card no longer flickers while runs come and go.** The card is written again only when its text changes.
- `fix` **Controls that show on hover keep their place.** The PDF bar's fold button and the file tree's row actions no longer push their neighbours aside.
- `fix` **The PDF bar's page selection looks like the bar's other buttons.**
- `perf` **The benchmark page shows the results for 0.2.5.** [`0a6f260`] [`247e3fb`]
- `fix` **A click into an empty table cell in the PDF puts the caret there.** A cell with no text, only spaces or a `~` has no word to click, so Type mode placed no caret. The caret now goes to the cell's place in the source, between its `&`s, drawn where the column's alignment sets the first letter, and typing fills the cell.
- `feat` **Rows and columns of a table are inserted, deleted and reordered from the PDF and the Typeset view.** A + stands on the line between two columns (under the table) or two rows (left of it) the pointer is near, a × under the pointer's column and left of its row; the controls stay while the pointer is on its way to them. They show once the pointer rests, muted until aimed at, and never during a drag (a column edge, a gap, a node) or with a menu open. The chip's name and the row's grip drag to reorder. A right click on a cell, in the PDF or the Typeset view, has Row and Column submenus. The table is rewritten as the table dialog writes it: the column spec, every row's cells, `\multicolumn` spans grown or shrunk, a rule moved with its row or column, `\cline` and `\cmidrule` renumbered. One undo takes it back.
- `feat` **The landing page's compile numbers: a 184-page thesis with figures, one measure throughout.** A one-edit rebuild of a generated thesis (TikZ and pgfplots figures every fifth page, hyperref) takes 1.5 s against latexmk's 2.0 s. Every ratio is latexmk's time over satex's, the number on top of each tile. That the output matches latexmk is said once, as a fact.
- `feat` **Typing in a table also wraps paragraph cells and moves `\multicolumn` spans and the column chips.** A `p`, `m`, `b` or `X` cell rewraps to its width and the rows below move down. A span keeps its place in its columns, and a span typed wider widens its last column. The column chips follow the echo.
- `feat` **Typing in a table cell moves the whole table at once.** The column widens or narrows for every row, the columns after it and the rules follow, and a centered table stays centered, so nothing jumps when the build lands. [`40766a3`](https://github.com/EagleoutIce/satex-analyzer/commit/40766a3)
- `feat` **Compile benchmarks: `satex compile` against latexmk and plain engine runs.** The benchmark page compares cold builds, rebuilds with nothing changed and rebuilds after one edit per document and toolchain (pdfTeX, LuaTeX, XeTeX), with whether the output is the same; the landing page shows the main numbers.

### LSP

- `perf` **Math font samples are drawn only when the font view asks for one.** Each costs a TeX run, and they held up every other preview (arrows, shapes, text fonts) until all were drawn.
- `perf` **Typing into a paragraph between generated text reuses the rest of the last run.** When the text after the paragraph comes from macros or a package (`\Blinddocument`), the last character the document set stayed on the edited line, so the run never met the last one and every keystroke ran the rest of the document again (4.4M steps, 2 s). A keystroke now meets the last run after the paragraph: 791 steps, 0.2 s.
- `feat` **A math command typed in text is set in math.** Completing `\sum`, `\frac` or a macro of your own that ends in math-only material where the text is text writes `\(\sum\)` with the caret inside, `$\sum$` in plain TeX or in a file that uses `$`, and never inside a formula. TeX's `Missing $ inserted` before such a command gets a safe quick fix that sets the command and its arguments in the same delimiters (`completion.wrap_math`, `conventions.math.inline`).
- `feat` **Every finding offers "Ignore here" and "Ignore rule".** The first writes `% satex-disable-next-line ⟨rule⟩` above its line, the second turns the rule off in the project's `satex.yaml`. No Fix all applies them.
- `fix` **TikZ previews are kept per installation**, and a picture that failed to draw is drawn again on the next ask.
- `fix` `TL 2019` **TikZ previews draw with TeX Live 2019's dvisvgm**, which has no `--exact-bbox`.
- `fix` **TikZ previews are kept in the run's cache directory** (`cache.dir`, `SATEX_CACHE`), not always in `~/.cache/satex`; a cut-off arrow tip is never kept or shown but drawn again, and two drawings at once no longer clear each other's pages.
- `perf` **A word typed into a paragraph of a long chapter is analyzed in its paragraph.** A paragraph whose lines are not known (a box or kern of unknown width in it) counts 1 to n lines, n its breakpoints: every typed word raised n, and the page's length with it, so the run after the edit met the last one only past the next forced page break. The bound is now rounded up to a power of two and stays as it was. A 150-page thesis: 12M → 0.84M steps per typed word (6.6–8.1 s → 4.2–4.6 s). A splice that fails at one line no longer keeps every later line from meeting the last run. `-vv` says what each part of serving an edit took and names the slowest rules.
- `perf` **The first word typed at a place no longer waits for the text before it.** The server places the states an edit resumes from and meets the last run at for the line of the caret (the last code action, highlight or completion request) while it is idle, and stops for any message. The same thesis: the first edit at a place 137M steps (29.9 s) → 0.84M, as every later one. `satex/runInfo` says what an edit's run still placed itself (`placedSteps`). The placing run passes states inside a paragraph, where no run can meet: a first edit in a 250-page document 5.8M → 4.0M steps and 4.2 → 0.9 s. Meeting the last run copies only the fact rows the edit changed.
- `perf` **A typed character no longer waits for the last one's findings.** The rules of a run stop at the next rule once a newer text came, and what a completion reads of the whole run is built while the server is idle (or by the first request that reads it), not before the findings. Meeting the last run after an edit writes only the rows, graph vertices and table entries the edit changed (a 150-page thesis: 0.5 s → 0.03 s of each edit). `-vv` says what each part of a splice, of concluding a run and of the lint took.
- `fix` **An alias's hover shows its manual once mined** (`\let\myspace\xspace`): a hover kept before the manual was read is asked again, and a hover that found no documentation is not kept for the next session.
- `fix` **`\caption` completes with its shape** (`[⟨options⟩]{⟨arg⟩}`): a command that errs alone is probed in the environment the document calls it in, else the one whose code it reads (`limits.probe_contexts`), and an environment entered for a probe gets the token its lookahead needs.
- `fix` **A chapter whose root stopped at a budget keeps its root.** The editor ran the chapter alone in a made-up document and reported its references as undefined.
- `perf` **Each build run's findings reach the editor at once, marked provisional** (`lsp.provisional`, on): a 737-page document shows its first findings after 11.6 s instead of 32 s; the final set is unchanged and replaces them.
- `fix` **Completions show a command's whole shape.** `\section` offers `*[⟨options⟩]{⟨arg⟩}`, ltcmd commands their `(…)` and `<…>` arguments, a `\def` its own delimiters; taking one writes the braces with the caret inside. The PDF page's list shows shapes and descriptions too, also while a run goes on.
- `fix` **Editors: a name built around unknown digits is the same name after an edit.** It named its number by the token's index, which a resumed run numbers differently than a run from the start, so findings and definitions spelled other names than `satex lint`.
- `fix` **Editors read the open `.bib` and root, not the files on disk.** An entry removed from an open `.bib` leaves its `\cite` undefined, an `\include` commented out leaves its chapter's labels undefined, and a `.bbl` or `.ind` the tool no longer makes is removed instead of kept stale.
- `fix` **Editors: an edited `.bib` or a commented-out `\include` gives the findings a fresh lint gives.** The build's bibliography and index files, the bibliography rules and the unread-file check read the editor's texts, not the files on disk. A `.bbl` or `.ind` the tool no longer makes is removed. An entry removed from an open `.bib` leaves its `\cite` undefined, and a reference to a label in an un-`\include`d chapter is undefined.
- `perf` **Playground edits about a fifth faster again.** A question a newer text made stale stops and answers nothing, the replaced run is freed after the reply, no checkpoint is replanted next to the edit, and the recursion and unused-package lints do less per run with identical findings.
- `perf` **Edits in the playground show findings twice as fast.** The edited paragraph's preview is the run itself up to the paragraph's end, not a second run; scope rows carried over an edit share their records; the typeset view indexes definition texts per file it needs; file lookups skip resolving directories no open buffer is in. A word typed in the spacing example: findings 0.8–1.15 s → 0.43–0.56 s, identical.
- `fix` **Editors rerun when a file the document reads changes on disk.** A kept run is reused only if the open texts match and every file it read or looked for is unchanged (the document cache's read log), so an edited `.bib` or `\input` file, or a file that now exists, is no longer served from a stale run.
- `fix` **Editors: findings follow edits, closes and reopens.** Closing an unsaved buffer reads the file from disk again, a reopened document gets its findings back, a file the document stops reading (an un-`\include`d chapter) runs again unless the run was cut short, and a file outside the root no longer overwrites the root's findings.

### Compile

- `fix` `TL 2019` **`satex compile` rests on TeX Live 2019**: the first pass's `.aux` follows the installed kernel, which never writes `\@abspage@last`.
- `perf` **`compile.warm` is on by default on Linux.** A build whose preamble has a format leaves one pdfTeX waiting for the next build in the same clock minute and says so; it ends a second after that minute. Small edits rebuild in about half the time.
- `perf` **XeLaTeX builds run their passes without the PDF driver and xdvipdfmx once at the end, as latexmk does; helpers that outlive a build release the locks and descriptors it inherited; a warm engine is taken only when TeX's environment is the build's.**
- `perf` **`satex compile` returns with the PDF.** Rule-level explanations come at once, the analysis runs detached and its findings show on the next call (`compile.wait` waits for them): a one-word edit of a big book returns in about latexmk's time instead of 18 s.
- `perf` **`satex compile` runs no draft pass and never waits for the preamble format.** A fresh build starts from latexmk's seed `.aux` and runs as many passes as latexmk; the format is dumped in the background; SyncTeX is compressed beside the pass. Cold builds 1.16× and edits 1.27× latexmk's speed on the benchmark subset, PDFs identical.
- `fix` **A build is one process group, ended when a newer one replaces it, its client goes away or `compile.timeout` passes.** Warm engines end after their minute, and a stopped server takes its build along: no orphaned pdflatex.
- `perf` **`satex compile` runs the analysis only for log messages it can explain.** A message with no source line (an underfull box while the output routine is active) no longer starts it: a one-word edit of a 1000-page book returns with its PDF, not 17 s later.
- `fix` **The progress bar counts packages built into caches, not only those loaded from them.** A first run after an update shows how many packages are done.
- `perf` **`satex compile`: the PDF first, the analysis only where a message needs it.** The build runs before the analysis, which runs only when the log has a message to explain and no stored explanation of the same messages, source, settings and read files holds: an unchanged 195-page book 1.7 s → 0.05 s with `compile.explain` on, the PDF of an edit in ~3 s instead of after the analysis. `compile.warm` works from the command line: the engine waits on a named pipe under `.satex-build` that it reads in the main file's stead, in the project's own directory, so no file of the project is touched and `\input{../shared}` reads as in a fresh build.
- `feat` **memoize: `satex compile` extracts memoize's externs itself.** No shell escape and no Perl module needed: the build runs memoize's TeX extraction between passes (`compile.memoize`).

### Analysis

- `perf` **A bibliography after its citations settles a run sooner.** Where `\bibliography` stands after every `\cite`, the first build run makes the `.bbl` itself when it looks for it and reads the entries: citation labels are known in run 2 instead of run 3 (`bib.early`, on). The build still compares it with the file made from the whole run, so a later citation sends it round again.
- `feat` **`limits.build_widen_after` names the build run after which changing lines are widened** (2, as before). `1` widens what the second run changed: one run fewer, with page numbers that moved read as unknown digits.
- `fix` **A beamer slide repeats a picture as exactly as the first slide.** Beamer typesets each slide from a copy of the frame's text. A conditional met again in that copy was taken for another pass of the same loop, summarized after three, and a picture's size became unknown on the second slide (false errors in rounded shadow boxes). A copy met at another place is now another call.
- `fix` **A run served from the package cache reports what a run that reads the packages reports.** Kept call effects were keyed by where a definition sat in memory, which a `\let` copy shares only in a run that reads the package. They are now keyed by the definition's text and shape, so cold and warm runs replay the same calls.
- `fix` **A run that ran out of Rust stack is not cached.** Where an expansion nests too deep, satex widens it; how deep it gets depends on the thread. Such a kernel, package segment or document result is no longer stored, so a later run never reads the widened state as if it were complete.
- `perf` **A package that loads other packages replays whole from its cache.** A cached package such as tagpdf now replays the packages it loads itself together with them, instead of reading again from each nested load. The cache fills one nesting level per run, so a package with nested loads replays whole by the third run.
- `fix` **A line-budget cut inside library code drops the whole call.** Library code that held some of the document's tokens as data (an l3fp expression, the items of a `\clist_map_inline:nn`) was kept as if it called the document's text, so satex read on in the middle of it with its outer calls gone: a second cut, many paths and false errors inside expl3 (an `\fp_set:Nn` loop under TeX Live 2026: 4.0M steps, now 1.9M). A cut inside a smaller library call drops only that call. [`fe0c47f`](https://github.com/EagleoutIce/satex-analyzer/commit/fe0c47f)
- `fix` **The kernel cache is keyed on the settings that change what it holds.** A kernel built under other limits or assumptions (`choices`, `assume_compiles` …) was loaded by every later run on the same cache directory, so a run's result depended on which run built the kernel first. Tracing and `controls`' own switches do not count [`080cf74`].
- `fix` `TL ≤ 2021` **`\creationdate` under an older XeTeX may print more than the date.** XeTeX before 0.999994 reads string-pool bytes after it. satex was sure of the date alone.
- `fix` **The names a file defines are found again for other definers.** A memo kept the first caller's answer for every later one.
- `fix` **`\parshape` with an unknown count reads its pairs as the shape's lines, and any count stays within the budgets** (`limits.parshape_lines`, default 64 kept). An unknown count left the pairs unread, so wrapfig's `\z@ \hsize` ran as an assignment and set `\z@` to 345pt. The next shape asked for 22 million lines and ran out of memory on TeX Live 2019.
- `fix` **A lint probe is bounded by steps, not the clock** (`limits.provider_steps`). A probe the clock stopped counted as "does not take the call" and was kept, so a finding could depend on machine load.
- `fix` **Without a configured year, satex reads the TeX Live whose `tex` is on `PATH`**, not the newest one under `/usr/local/texlive`.
- `perf` **A call that forked learns its effect even where its runs wrote different names** (`call-learned-effect`). A name only some runs wrote is widened, and a result some run left a number in counts as a number. `\pgfmathparse` in a `\loop` was refused a summary, ran in full each pass and kept forking: a typed-number parse took 45.7M steps on TeX Live 2022, now 708k.
- `fix` **A widened expl3 variable keeps the form of its kind** (assumption `variable-kind-shape`, `analysis.assume_variable_kind_shape`). An fp widened after a cut lost l3fp's delimiters, so `\fp_use:N` ran away to the end of the file on TeX Live 2019 and 2022. The form comes from the kind's own constants as the run defined them.
- `fix` **LuaTeX finds a font by its name, as luaotfload does** (`\setmainfont{Libertinus Serif}`). A font given by name was unknown, so fontspec's checks of its bold and italic faces forked without end: over a billion steps on TeX Live 2022, now under a million. `\fontname` of a face requested twice is the first request's, as in LuaTeX.
- `fix` **A package cache stays served when lines above the load move.** TeX Live 2019's kernel keeps the `\usepackage` tokens in `\@currname`, so every cache key held document positions and an added line made all caches stale. Positions in project files are now keyed as placeholders and replayed where the text stands now.
- `fix` `TL 2019` **A class whose last line inputs a project file is cached to its end**, and a limit a cached load reached is named once on replay.
- `fix` `TL 2019` **Options of a repeated load reach the option-clash check on TeX Live 2019**, whose kernel has no `\@onefilewithoptions@clashchk`.
- `fix` `TL 2019` **`\{` and other symbols read as TeX Live 2019's `tuenc.def` declares them** (`\DeclareTextSymbol` with `\UnicodeEncodingName`).
- `fix` **`\openin` of the job's log is not at its end**, and a label like `Step\nobreakspace 2` gives the word "Step" (TeX Live 2022).
- `fix` **`\XeTeXglyphname` on a TFM font leaves the number unread**, as xetex does.
- `fix` **A digit slice open to the end of a number has no known width.** It overflowed and gave exactly 2147483647 in release builds.
- `fix` `TL 2019` **Biber's `datatype=date` constraint no longer flags dates.** Only ISBN, ISSN and ISMN values are checked for their check digit.
- `fix` `TL 2019` **Package completion works on TeX Live 2019**: the kernel's hooks for a missing package no longer decide what the argument is.
- `fix` **A replayed package load counts its errors toward TeX's hundred.** A cold run that gave up at the hundredth error and a warm run that read on now agree: the replay restores the error count, and a load cut at the hundredth error is not replayed past it.
- `fix` `TL 2022` **The job's log exists while the job runs.** `\IfFileExists{\jobname.log}` is true and its size and date are unknown, as in TeX, which opens the log before the first line. TeX Live 2022's tagging took its XMP date from the log, got `\q_no_value` and spent 500M steps at `\end{document}`.
- `fix` `TL 2022` **A kernel cut by `limits.format_steps` no longer leaves its files to the document.** The document read latex.ltx and expl3 on as its own text and ran for minutes on TeX Live 2022.
- `perf-fix` **A package the document or kernel opens before loading it is cached again.** Older kernels' `\IfFileExists` open each file with `\openin` first, and such a package never got its cache.
- `fix` **`\openin` only opens a file, and its text is read at the first `\read`.** A file that is only tested for existence no longer ties the run to its content, so an edit there resumes inside it instead of rerunning from the main file.
- `perf-fix` **A package that opens and closes its own stream is served from its cache while the document holds another stream open.**
- `fix` **satex asks the installed engine which primitives it has**, so an older LuaTeX or XeTeX is no longer said to define `\partokenname` or `\showstream`.
- `fix` `TL ≤ 2022` **Older kernels (TeX Live 2019, 2022) report a repeated `\usepackage` and its option clash**, and a label built from a counter is recorded expanded where `\protected@write` writes inside its group.
- `perf` **A build holds one run at a time, and the call memo is bounded by bytes (`limits.call_memo_bytes`, 256 MiB).** A 100-page thesis's second build run no longer stops at the memory limit (peak 7.8 → 5.0 GiB).
- `feat-fix` **`limits.seconds` defaults to 600, and a probe of a package for a missing command has its own `limits.probe_seconds` (20).** A probe ran without any time limit and kept a lint of a misspelled `\usepackage` going for minutes.
- `fix` **A walk through joined texts no longer hangs inside one step.** A text that names the one-of of the pass before many times was followed once per name, 20^8 times for twenty copies eight passes deep. Every walk through one-of texts and macro bodies now pays one budget per step (`limits.walk_texts`, 100000), past which the rest reads as unknown.
- `fix` **A cut recursion no longer hangs counting what the dropped text would close.** Each macro is counted once; acmart's title with `\maketitle` inside `\affiliation` ran past `limits.seconds` for minutes.

The title box has its height and acmart's title loop is decided.

- `fix` **Two-column classes ship the page at `\clearpage`.** What the output routine leaves on its list goes back to the page builder item by item, and a forced penalty there fires the routine again (tex.web § 1026): `\documentclass[twocolumn]{article}` with `x\clearpage` is on page 2 with one page shipped, as pdflatex has it, where satex said page 1 and none.
- `fix` **Tokens TeX ignores (`\relax`) before a command no longer change the findings**; an argument read from unknown text that may be empty keeps both readings and never swallows the text behind it; a path dropped as not compiling no longer keeps the rest of a package out of its cache.

- `fix` **Code that assigns for long without reading source (a `\foreach` over many TikZ nodes) no longer aborts on memory**: the write log keeps one entry per name and group depth past `limits.write_log`.

- `feat` **`limits.nesting` (300)**: how deeply steps nest inside scans and quantities inside quantities before the nesting is widened, configurable like every other limit.
- `fix` **An argument the document begins and never closes is an error** (`\cite[p.~3` before `\end{document}`): pdflatex stops with "File ended while scanning use of …"; satex said nothing, since the end was met inside library code.
